# Пример: «Цеховая себестоимость. Участок 1»

Реплика decomposition-tree диаграммы из Power BI (изначально — DAX-мера
`4505_card_SVG_switch`, свитчащая между card_type 1–5 в таблице
`4505_Участок_1`), собранная для виджета `ElemSvg` в режиме `cardMode` +
`factorPanel`.

## Файлы

- **`cehovaya-sebestoimost-uchastok1.svg`** — рабочий файл для загрузки в
  свойство `svg` виджета. Только формы (прямоугольники карточек, линии-коннекторы,
  прямоугольник панели «Отклонение») — **без** зашитого текста нигде: и
  заголовок/факт/%/план внутри каждой карточки (`cardMode`), и итог + список
  строк панели «Отклонение» (`factorPanel`) рисует сам виджет из датасета.
  Не путать со вторым файлом ниже — если загрузить его вместо этого, текст
  будет задваиваться (статичный из SVG + динамический поверх от виджета),
  как только реальные данные разойдутся со снимком на скрине.
- **`cehovaya-sebestoimost-uchastok1-static-preview.svg`** — тот же макет, но со
  всем текстом, зашитым прямо в SVG (значения — снимок с оригинального скрина
  Power BI). Годится только как статичная картинка/референс для сверки,
  **не для использования с `cardMode`/`factorPanel`**.
- **`sample-dataset.json`** — 32 строки:
  - 22 показателя дерева (по одному на карточку) с полями под `cardFields` ниже;
  - 1 строка-«шапка» панели «Отклонение» (`id: "deviation_panel"`, поле `total`);
  - 9 строк-факторов этой панели (`panelId: "deviation_panel"`, поля `rowType`
    / `label` / `value` / `order`) — именно столько их в апрельском снимке;
    в другом периоде строк может быть больше или меньше, панель подстраивается
    сама (см. «Почему панель раньше была статичной» ниже).

## Как подключить

1. **Настройки объектов** → загрузить `cehovaya-sebestoimost-uchastok1.svg` в
   поле `SVG`. Каждая карточка и панель — это `<g id="...">` с тем же `id`,
   что и в `sample-dataset.json` (`cehovaya_sebestoimost`, `obem_proizvodstva`,
   …, `deviation_panel`) — по умолчанию `data-id = id`, переименование не
   требуется.
2. Подключить датасет с содержимым `sample-dataset.json` (32 строки).
3. **Измерения/метрики**:
   - `fields.metricId` → `id`
   - Включить **«Режим карточек показателей»** (`cardMode`)
   - `cardFields.titleField` → `name`, `titleField2` → `name2`
   - `cardFields.valueField` → `fact`, `planField` → `plan`
   - `cardFields.positiveDirectionField` → `direction` (`'up'` = рост зелёный,
     иначе — падение зелёное)
   - `cardFields.highlightField` → `highlight`
   - В коллапсе «Готовый текст вместо формата» — `valueDisplayField` → `fact_display`,
     `planDisplayField` → `plan_display`, `percentDisplayField` → `percent_display`
     (в датасете у показателей разная точность: `716` / `22,00` / `5,0` — один
     общий числовой формат для всех не подходит, поэтому в примере используется
     готовый текст, а `fact`/`plan` остаются числами только для расчёта знака
     отклонения и стрелки)
   - Включить **«Режим панели отклонений»** (`factorPanel.enabled`)
   - `factorPanel.nodeIds` → `deviation_panel`
   - `factorPanel.totalField` → `total`
   - `factorPanel.totalLabel` → `Отклонение, тыс. Р`
   - `factorPanel.groupField` → `panelId`
   - `factorPanel.orderField` → `order`
   - `factorPanel.typeField` → `rowType`
   - `factorPanel.labelField` → `label`
   - `factorPanel.valueField` → `value`

## Почему подсветка и панель «Отклонение» раньше были статичными — и почему это баг

В реальном отчёте оба меняются вместе с фильтром периода (проверено на видео:
переключение месяца в Power BI одновременно меняет и цифры, и то, какие
карточки подсвечены красным, и — для панели «Отклонение» — сам список факторов
(3 строки в одном периоде, 9 в другом, разные подписи/суммы). Ни то, ни другое
не описывается одним фиксированным снимком:

- Подсветка карточек — уже была решена правильно с самого начала: она читается
  из `cardFields.highlightField` на **каждой** перерисовке (`updateSvg`
  пересобирает узлы заново при каждом обновлении датасета), так что при смене
  периода через переменную хранилища подсветка обновится сама.
- Панель «Отклонение» — **была статичной по ошибке**: `card()` (карточки) уже
  рисовал только форму ещё в предыдущем фиксе, а `deviation_panel()` продолжал
  печатать весь текст (итог + 9 строк факторов) прямо в SVG. Пока тестовые данные
  совпадали со снимком, это было незаметно — статичный и динамический слои
  просто накладывались друг на друга один в один. Как только период меняется
  (другое число факторов/сумм), тексты расходятся и накладываются друг на
  друга (двоение). Это и обсуждалось в чате.

Исправлено: `deviation_panel()` теперь тоже рисует только прямоугольник, а весь
текст (итог + переменное число строк bold/section/item) строит виджет через
новый режим `factorPanel` — по тому же принципу, что и `cardMode`, только
итог берётся из одной строки (найденной как обычно по `fields.metricId`), а
сами строки списка — из ДРУГИХ строк датасета, у которых `factorPanel.groupField`
равен id этой строки-панели. Высота прямоугольника панели пересчитывается
на лету под фактическое число строк.

Проверено сборкой всей цепочки (реальный `SvgViewModel`/`SvgUtils`, оба SVG-файла,
этот датасет) через jsdom + Playwright — рендер идентичен исходному скрину
Power BI (подсветка 4 карточек, зелёные/красные стрелки, 1-/2-строчные заголовки,
9-строчная панель «Отклонение»), и отдельно проверено на «искусственном» втором
периоде с другим числом факторов — панель верно показывает только актуальные
строки и не тянет за собой старые.

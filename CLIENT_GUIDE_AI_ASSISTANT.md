# Запуск среды разработки виджетов Insight + офлайн ИИ-помощник

Инструкция для тех, кто только начинает и хочет, чтобы код писал ИИ по
вашим словесным описаниям — без интернета, бесплатно, ничего никуда не
отправляется.

Вам прислали большой (~12GB) архив
**`insight-widgets-client-package.zip`** — в нём, кроме самой среды
разработки, уже лежит локальная ИИ-модель. Она весит несколько
гигабайт, поэтому архив большой и распаковывается не мгновенно — это
нормально.

---

## Что за ИИ внутри и чего от него ждать

Модель — **Qwen2.5-Coder 14B**, открытая (бесплатная) модель от Alibaba,
специально обученная писать код. Коротко, что важно понимать:

- Справляется с типовыми задачами: добавить настройку виджету, поправить
  стиль, создать несложный виджет по образцу существующего.
- Это **не** уровень ChatGPT/облачного ИИ в Cursor — иногда придётся
  переформулировать запрос или поправить результат руками.
- Работает на вашем компьютере (CPU, без видеокарты) — ответ занимает
  **2-5 минут**, это не зависание, а особенность локальной генерации без
  GPU. Крупная задача — дольше, короткая правка — быстрее.
- Всё работает офлайн: после первого запуска интернет не нужен вообще.

## Что нужно установить заранее

- **Docker Desktop**: [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/)
- **Cursor** (редактор кода со встроенным ИИ-интерфейсом):
  [cursor.com](https://cursor.com/) — установите как отдельную
  программу.

## Шаги запуска

**Шаг 1. Распакуйте архив в новую пустую папку.**

Важно: если у вас уже была папка с предыдущей версией архива — не
распаковывайте новый zip поверх неё. Создайте новую папку или сначала
полностью удалите старую, иначе часть файлов может остаться от старой
версии и всё будет работать не так, как ожидается.

**Шаг 2. Откройте Cursor** → `File` → `Open Folder` → выберите
распакованную папку.

**Шаг 3. Откройте терминал внутри Cursor** (важно: именно встроенный
терминал Cursor, не отдельное окно PowerShell/Terminal): меню
`Terminal → New Terminal`, либо `` Ctrl+` `` (Windows) / `` Cmd+` ``
(Mac).

**Шаг 4. В терминале выполните по очереди:**
```
docker load -i insight-widgets.tar.gz
docker load -i insight-ollama.tar.gz
docker compose --profile ollama up -d
```
Дальше покажите ссылки, которые реально поднялись:
```
.\scripts\print-urls.ps1
```
(на Mac — `./scripts/print-urls.sh`)

Должны появиться две строки:
```
Виджеты:      http://localhost:3001
ИИ-ассистент: http://localhost:11434
```
Если видите обе — всё запущено, идём дальше.

---

## Шаг 5. Установите расширение Twinny в Cursor

1. В Cursor откройте панель **Extensions** (значок в левой боковой
   панели).
2. Найдите **Twinny**, нажмите **Install**.
3. Всё — регистрация не нужна, Twinny сама находит локальную модель на
   `http://localhost:11434`. Если по какой-то причине не подхватила
   автоматически — в настройках Twinny укажите модель
   `qwen2.5-coder:14b` вручную.

## Шаг 6. Как этим пользоваться

Откройте боковую панель Twinny (значок появится в Cursor после
установки) — это чат с ИИ. Пишете задачу словами, например:

> Создай виджет ElemHelloWorld по образцу ElemButton

> Объясни, что делает этот файл

> Добавь виджету настройку цвета текста

ИИ предложит код/правки — проверьте перед тем как соглашаться
применить, как с любым ИИ-ассистентом. Ответа нужно подождать (2-5
минут, см. выше) — панель не зависла, модель думает.

## Подключение виджета к редактору платформы (`$elem.add`)

Когда виджет готов и dev-сервер виджетов запущен (`http://localhost:3001`
из шага 4):

1. Откройте в браузере страницу редактора платформы Insight, зайдите в
   свой проект.
2. Откройте консоль разработчика: `F12` → `Console`.
3. Выполните:
   ```js
   $elem.add({
       types: ['ElemHelloWorld'],
       url: 'http://localhost:3001'
   });
   ```
   (`types` — имя вашей папки в `./src`).

Виджет появится на панели инструментов редактора.

## Если нужно пересобрать виджеты (не выключая ИИ)

ИИ-модель можно оставить работать постоянно и не трогать её при
правках виджетов. Пересобираем/перезапускаем **только** виджеты —
командой `down`/`up -d` **без** `--profile ollama`:
```
docker compose down
docker compose up -d
.\scripts\print-urls.ps1
```
Так `ollama` не остановится и не потребует повторной загрузки.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен — откройте приложение, дождитесь, пока значок кита в трее перестанет анимироваться |
| В обычном чате Cursor пишет «Named models unavailable» | Это ограничение бесплатного тарифа Cursor — не страшно, мы работаем через Twinny, а не встроенный чат Cursor |
| `no such service: ollama` при `docker compose --profile ollama up` | Архив распакован поверх старой папки, файл `docker-compose.yml` остался от старой версии — распакуйте заново в чистую пустую папку |
| `print-urls.ps1` показывает кракозябры вместо русского текста | Убедитесь, что используете актуальный архив (в старых версиях была такая проблема с кодировкой, уже исправлено) |
| Twinny не видит модель | Проверьте, что контейнеры реально запущены: `docker compose ps` — оба (`widgets-dev`, `ollama`) должны быть `running` |
| Ответ ИИ долго не приходит | На CPU это нормально — 2-5 минут на ответ, не зависание. Если ждёте дольше 10 минут — проверьте `docker compose logs ollama` |

Если что-то не получается — пришлите текст ошибки как есть (скриншот
или копию из терминала/консоли браузера) — так разобраться получится
быстрее, чем по общему описанию.

# Запуск среды разработки виджетов Insight + офлайн ИИ-помощник

Инструкция описывает запуск среды разработки виджетов с локальным
ИИ-ассистентом, который генерирует код по текстовому описанию задачи.
Работает без подключения к интернету, без подписок; данные не покидают
компьютер.

Архив **`insight-widgets-client-package.zip`** (~12GB) содержит среду
разработки и локальную ИИ-модель. Модель занимает несколько гигабайт,
поэтому распаковка архива может занять продолжительное время.

---

## Что за ИИ внутри и чего от него ждать

Модель — **Qwen2.5-Coder 14B**, открытая (бесплатная) модель от Alibaba,
обученная на генерации кода. Ключевые характеристики:

- Справляется с типовыми задачами: добавление настройки виджету,
  правки стиля, создание несложного виджета по образцу существующего.
- По качеству уступает облачным моделям (ChatGPT и аналогичным) — в
  отдельных случаях требуется уточнить формулировку запроса или
  скорректировать результат вручную.
- Генерация выполняется на CPU без GPU — время формирования ответа:
  **2-5 минут** в зависимости от объёма задачи.
- Работает полностью офлайн: после первого запуска подключение к
  интернету не требуется.

### Как проверяли и что реально получилось

Модель проверяли на практической задаче из проекта: использовался
`src/ElemButton/descriptor.js` (в нём соседние `btn*`-пропсы хранятся
как обычные строки, например `btnBorderRadius: '8px'`) с дословной
цитатой правила «Universal Dimension Settings Pattern» из
`.cursor/rules/widget.mdc`. Модели поставили задачу добавить новый проп
`btnIconGap` **по правилу**, а не по соседнему коду в этом же файле —
то есть корректный ответ требовал не скопировать окружающий стиль, а
применить инструкцию поверх него. Задача усложнена намеренно: в таких
случаях модели обычно копируют стиль соседних строк вместо того, чтобы
следовать правилу.

| Модель | Скачано | RAM при загрузке | Время на задачу | Скорость генерации | Качество |
|---|---|---|---|---|---|
| qwen2.5-coder:7b | 4.7GB | ~6GB | 3.5 мин | ~4.4 ток/с | Правило применено верно, но ответ избыточен — модель повторила пример из инструкции вместо того, чтобы вывести только новый проп |
| **qwen2.5-coder:14b** (в этом архиве) | 9GB | ~10GB | 2.5 мин | ~2.1 ток/с (ниже, но за счёт более короткого и точного ответа итоговое время меньше) | Правило применено верно, ответ точнее и без лишнего — пример из инструкции не копировался |

Тест проводился на машине без видеокарты (4 CPU, 15GB RAM) — то есть
на менее производительном оборудовании, чем у большинства современных
ноутбуков; на вашем компьютере скорость, скорее всего, будет не хуже. В
архиве используется `qwen2.5-coder:14b`: генерация медленнее в
пересчёте на токен, но результат точнее и без лишнего текста.

## Шаги запуска

**Шаг 1. Распакуйте архив в новую пустую папку.**

Важно: если ранее уже была распакована предыдущая версия архива — не
распаковывайте новый zip поверх той же папки. Создайте новую папку или
предварительно удалите старую: иначе часть файлов может остаться от
предыдущей версии, и среда будет работать некорректно.

**Шаг 2. Откройте VS Code** → `File` → `Open Folder` → выберите
распакованную папку.

**Шаг 3. Откройте терминал внутри VS Code** (используется встроенный
терминал VS Code, а не отдельное окно PowerShell/Terminal): меню
`Terminal → New Terminal`, либо `` Ctrl+` `` (Windows) / `` Cmd+` ``
(Mac).

**Шаг 4. В терминале выполните по очереди:**
```
docker load -i insight-widgets.tar.gz
docker load -i insight-ollama.tar.gz
docker compose --profile ollama up -d
```
Далее выведите ссылки на запущенные сервисы:
```
.\scripts\print-urls.ps1
```
(на Mac — `./scripts/print-urls.sh`)

Ожидаемый результат — две строки:
```
Виджеты:      http://localhost:3001
ИИ-ассистент: http://localhost:11434
```
Если обе присутствуют — среда запущена, можно переходить к следующему
шагу.

---

## Шаг 5. Установите расширение Twinny в VS Code

1. В VS Code откройте панель **«Расширения»** (значок в левой боковой
   панели).
2. Найдите **Twinny**, нажмите **Install**.
3. Регистрация не требуется — Twinny автоматически определяет
   локальную модель по адресу `http://localhost:11434`. Если модель не
   определилась автоматически — укажите её вручную в настройках
   Twinny: `qwen2.5-coder:14b`.

## Шаг 6. Как этим пользоваться

После установки в VS Code появится боковая панель Twinny — интерфейс
чата с ИИ. Задача формулируется текстом, например:

> Создай виджет ElemHelloWorld по образцу ElemButton

> Объясни, что делает этот файл

> Добавь виджету настройку цвета текста

ИИ предложит код или правки — результат следует проверять перед
применением, как и в случае с любым ИИ-ассистентом. Формирование
ответа занимает 2-5 минут (см. раздел выше).

**Правила проекта.** В репозитории есть свод правил разработки
виджетов — `.cursor/rules/widget.mdc`, `WIDGET_REFACTORING_SPEC.md` и
`docs/ai-playbook/ai-playbook-summary.md`. Локальная модель не
подключает их автоматически (в отличие от Cursor), поэтому при
обращении к ИИ указывайте путь к файлу правил прямо в запросе,
например:

> Создай виджет ElemHelloWorld по образцу ElemButton, следуя правилам
> из docs/ai-playbook/ai-playbook-summary.md

Без этого модель будет ориентироваться только на код в открытых
файлах и может не учесть требования проекта (структуру каталогов,
`propChanged`, формат размерных пропсов и другие обязательные
паттерны).

## Подключение виджета к редактору платформы (`$elem.add`)

Когда виджет готов и dev-сервер виджетов запущен (`http://localhost:3001`
из шага 4):

1. Откройте в браузере страницу редактора платформы Insight, зайдите в
   свой проект.
2. Откройте консоль разработчика: `F12` → `Console`.
3. Выполните:
   ```js
   $elem.add({
       types: ['ElemHelloWorld'],
       url: 'http://localhost:3001'
   });
   ```
   (`types` — имя вашей папки в `./src`).

Виджет появится на панели инструментов редактора.

## Если нужно пересобрать виджеты (не выключая ИИ)

ИИ-модель может оставаться запущенной постоянно и не требует остановки
при правках виджетов. Пересобирать/перезапускать нужно **только**
виджеты — командой `down`/`up -d` **без** `--profile ollama`:
```
docker compose down
docker compose up -d
.\scripts\print-urls.ps1
```
При таком порядке `ollama` не останавливается и повторной загрузки не
требует.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен — откройте приложение, дождитесь, пока значок кита в трее перестанет анимироваться |
| `no such service: ollama` при `docker compose --profile ollama up` | Архив распакован поверх старой папки, файл `docker-compose.yml` остался от предыдущей версии — распакуйте архив заново в чистую пустую папку |
| `print-urls.ps1` выводит некорректные символы вместо русского текста | Убедитесь, что используется актуальная версия архива (проблема кодировки встречалась в ранних версиях, впоследствии устранена) |
| Twinny не определяет модель | Проверьте, что контейнеры запущены: `docker compose ps` — оба (`widgets-dev`, `ollama`) должны быть в статусе `running` |
| Ответ ИИ формируется дольше ожидаемого | Время генерации на CPU — 2-5 минут. При превышении 10 минут проверьте `docker compose logs ollama` |

При возникновении проблем, не описанных выше, приложите текст ошибки в
исходном виде (скриншот или копию из терминала/консоли браузера) — это
ускорит диагностику.

# Запуск среды разработки виджетов Insight — для разработчиков

Инструкция предназначена для разработчиков, работающих в собственном
редакторе кода. Ниже — минимальный набор команд для запуска среды без
дополнительных пояснений базовых операций.

Вам прислали **`insight-widgets-client-package.zip`**. В нём уже готовый
Docker-образ со всем необходимым (Node.js, зависимости платформы) — свой
`node_modules` собирать не нужно.

---

## Что нужно установить заранее

- **Docker**: [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  (Windows/Mac) или Docker Engine (Linux).
- **Редактор кода** — любой, на ваш вкус. Если своего нет, рекомендуем
  [VS Code](https://code.visualstudio.com/) — бесплатный, лёгкий, с
  нормальной поддержкой Vue/JS из коробки.

## Шаги

**Шаг 1.** Распакуйте `insight-widgets-client-package.zip` в рабочую
папку.

**Шаг 2.** Откройте терминал прямо в этой папке:
- **Windows**: в проводнике зайдите в папку, зажмите `Shift` и кликните
  правой кнопкой по пустому месту → «Открыть окно PowerShell здесь»
  (или «Открыть терминал здесь» в новых версиях Windows).
- **Mac**: откройте `Terminal` (Spotlight → `Terminal`), затем
  `cd путь/до/распакованной/папки`.

**Шаг 3.** Загрузите образ и запустите:
```
docker load -i insight-widgets.tar.gz
docker compose up
```

**Шаг 4.** Дождитесь в терминале строки:
```
App running at: Local: http://localhost:3001
```
Значит dev-сервер поднят. Из интернета при этом ничего не скачивается —
образ уже лежит в распакованной папке. Терминал не закрывайте (он же
держит сервер) — просто сверните окно.

Если порт `3001` занят чем-то другим — поменяйте `"3001:3001"` на,
например, `"3002:3001"` в файле `docker-compose.yml` и используйте
`localhost:3002` дальше.

**Шаг 5.** Откройте в редакторе ту же распакованную папку (`File → Open
Folder` в VS Code или аналогично в вашем редакторе). Файлы виджетов —
в `./src`, эта папка примонтирована в контейнер: правки сразу
подхватываются dev-сервером, пересборка вручную не нужна.

---

## Правила и конвенции проекта

Перед тем как писать код, ознакомьтесь со стандартами разработки
виджетов — они обязательны независимо от того, пишете вы код сами или
с помощью ИИ:

- **`widget.mdc`** — архитектура виджета, обязательные
  паттерны (`propChanged`, `{size, unit}` для размерных пропсов,
  `unit2PxMixin`, работа с датасетом), запрещённые практики.
- **`WIDGET_REFACTORING_SPEC.md`** — стандарт панелей «Оформление» и
  «Я дизайнер», интеграция с Vuex.
- **`docs/ai-playbook/ai-playbook-summary.md`** (и парный
  `ai-playbook-summary.json`) — компактный свод тех же правил в
  машиночитаемом виде, дополнен паттернами регистрации переменных
  датасета и синхронизации фильтров между виджетами
  (`$storeCommit`/`$storeWatchHandler`, `$storeMeta.setVar()`).

Следование этим правилам обеспечивает единообразие кода и совместимость
с остальными виджетами платформы.

## Подключение виджета к редактору платформы (`$elem.add`)

Чтобы виджет появился на панели инструментов редактора Insight:

1. Убедитесь, что dev-сервер запущен (шаг 4 выше).
2. Откройте в браузере страницу редактора платформы, зайдите в свой
   проект.
3. Откройте консоль разработчика браузера: `F12` → вкладка `Console`.
4. Вставьте и выполните:
   ```js
   $elem.add({
       types: ['ElemCalendar', 'ElemAccordion'],
       url: 'http://localhost:3001'
   });
   ```
   - `types` — имена виджетов (папки в `./src`), которые нужно
     подключить.
   - `url` — адрес вашего dev-сервера. Если браузер и контейнер на
     одной машине — `localhost:3001`. Если редактор открыт с другого
     устройства — укажите IP машины с контейнером в локальной сети
     (например, `http://192.168.10.172:3001`).

Виджеты сразу появятся в палитре редактора и будут подтягиваться прямо
из вашей локальной среды — билд и деплой на сервер для проверки не
нужны.

`$elem.remove()` в той же консоли отключает подключённые виджеты (после
— обновите страницу редактора).

## Пересборка / перезапуск

Если после создания **нового** виджета он не подхватился (dev-сервер
иногда не сразу замечает только что созданные файлы, в отличие от
правок в существующих) — в терминале, где выполняется `docker compose
up`, нажмите `Ctrl+C`, затем:
```
docker compose down
docker compose up
```
Это пересоздаёт контейнер и гарантированно подхватывает все текущие
файлы проекта.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен — откройте приложение, дождитесь, пока значок кита в трее перестанет анимироваться |
| `port is already allocated` | Порт `3001` занят — смените на `3002:3001` в `docker-compose.yml`, используйте `localhost:3002` |
| `$elem` не определён в консоли браузера | Обновите страницу редактора — объект создаётся при загрузке страницы |
| Виджет не появился после `$elem.add` | Проверьте, что `types` совпадают с именами папок в `./src` (например, `ElemAccordion`, а не `elem-accordion`), и что `url` открывается в браузере напрямую |
| Изменения в коде не видны в редакторе | Убедитесь, что контейнер и dev-сервер ещё работают — смотрите лог в терминале (`docker compose logs -f`, если запускали в фоне через `-d`) |

Если что-то не получается — пришлите текст ошибки как есть (скриншот
или копию из терминала/консоли браузера).
